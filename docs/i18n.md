# Language

Two catalogues, `en` (the source) and `fr`. Nothing in either is generated: a
key that exists in one and not the other ships as a blank label for half the
readers, so the parity rules are a test, not a checklist.

| Where | Catalogue | Locale comes from |
|---|---|---|
| web | `web/src/i18n/{en,fr}.json` | `navigator.language`, `fr*` → French, English otherwise |
| server | `server/src/i18n/{en,fr}.json` | the request's `Accept-Language`, first tag the catalogue covers, English when there is none |

## 1. Keys

`area.thing` for a label, `area.thing.detail` for a second line, `error.<code>`
for the wire envelope. A key names where the string is used, never what it says:
`auth.signIn.submit`, not `auth.signIn.go`.

## 2. The parity rules

`server/test/i18n.test.ts` reads all four files and applies one set of rules to
both packages: the same keys in both languages, no empty value, the same
`{placeholders}` in both, no emoji. It also fails when `ErrorCode` grows a member
without copy in both languages — the union in `server/src/lib/errors.ts` is the
list of codes the API can answer, so a code without a message is a code that
would reach a reader as `error.some_new_code`.

## 3. Fallback

A missing key falls back to English, then to the key itself. A reader never sees
a blank, and the fallback is visible in a test rather than in production. The
same two steps apply on the server (`translate`), where the third argument is the
sentence the caller already had, so an old call site keeps its text.

## 4. What is translated, and what is not

Translated on the server: the error envelope's `message` for every code, the
validation hint, the reset mail, the digest unsubscribe page.

Not translated in 2.0, and named here so it is a decision:

- **Logs.** `AppError.message` stays the English sentence whatever the request
  asked for. A log line, a request id and a pasted stack trace must read the same
  way in every incident.
- **Hints at the call site.** `new AppError('rate_limited', {hint: '…'})` writes
  an English sentence; only hints given as a key (`hintKey`) are translated. The
  sweep is mechanical and is what K5-08's settings screen will motivate.
- **The digest body.** Its sections are computed text sent to a channel; the
  account's language is not stored, so it stays English until a locale column
  exists (2.1).
- **The MCP endpoint.** `-32xxx` messages are protocol strings, not UI copy.
