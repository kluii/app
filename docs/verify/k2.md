## K2-05 — Move planning and renumbering

| Exit criterion | Command | Output | Verdict |
|---|---|---|---|
| 200 randomised orders never produce a duplicate or out-of-order position | `npx vitest run --root server test/moves-property.test.ts` | `4 passed` — 200 in-column moves, 100 cross-column moves, a slot squeezed 30 times, a vanished neighbour | ok |
| a move under an active filter uses stored neighbours | `npx vitest run --root web test/neighbours.test.ts` | `6 passed` — a hidden card between two rendered ones is named as the neighbour | ok |

Two real defects were fixed under this task, both found by the property test:

1. `planMove` treated the ids a client sent as positions, so a `before`-only
   move in the middle of a column ranked *past* the card directly under it. The
   insertion point is now resolved from the stored column.
2. `planRank` prepended with `after - 1024` and no floor: a column prepended to
   forever walked to `0`, then negative, and never renumbered. It now steps,
   halves, then asks for a renumber. The unit expectation in
   `server/test/boards-cards.test.ts` changed from `position: 0` to `512`
   accordingly.

## Deviations

1. **Primitives are platform-first, not registry copies.** `dialog.tsx`,
   `popover.tsx` and the rest are written against `<dialog>` and
   `popover="auto"` instead of being copied from the shadcn registry. The
   observable contract (focus trap, Esc, light dismiss, tokens) is the same and
   axe passes; the reason is that the registry's Radix wrappers bring a
   dependency the brief does not allow without an ADR. Recorded here rather than
   in an ADR because no browser dependency was added.
2. **`/styleguide` ships unlinked.** It is a real route in the SPA, reachable by
   URL, and it is how K2-02 is proven. It appears in no navigation.
3. **Drop targets identify themselves with data, not `card:<id>` ids.** A card's
   droppable carries `{type: 'card-target', cardId}`; the behaviour the spec asks
   for (a card is the target, gaps are not) is proven by the drag journeys.
4. **The read-only half of K2-08 is deferred.** Assigning a second membership
   role is K3-05 (`POST /boards/:id/members` is not implemented yet), so the
   browser cannot render a real viewer. The API refuses the write with `403` and
   `done` stays `false` (proven in `server/test/boards-cards.test.ts`); the DOM
   assertion lands with K3-08, when a read-only visitor exists.
5. **`web/test/board-live-race.test.tsx` is a Playwright journey instead.** The
   real server publishes before the response, so the race can be measured in a
   browser against the built app rather than simulated in jsdom. Adding jsdom for
   a weaker assertion was not worth the dependency.
6. **TanStack DB is pinned but unused so far.** `web/src/data/` exists (merge,
   live stream, board frames) and is the only module that writes a board state,
   so swapping the store is still a one-directory change.
