Approval writes **one** event (`pending.approved`): the card exists because someone
decided, and a second `card.created` row would claim the anonymous actor created it
live. The expiry sweep runs on a five-minute interval in `server.ts`, guarded by
`pg_try_advisory_xact_lock('klui:pending-sweeper')` so two instances cannot both purge.

### What this task added to the contract

- `POST /boards/:id/anon` `{label}` → `200 {board_id, label, actor_kind}` and a signed
  `klui_anon` cookie (12 h, httpOnly, `SameSite=Lax`). It refuses a private board with
  `404` and `anon_write: off` with `403`.
- `GET /boards/:id/public` — the board's name, visibility and anon policy for a
  credential-less visitor, so the SPA can offer the gate instead of a bare 401.
  A private board answers `404`.
- `CallerDto` now carries one boolean per affordance (`can_delete_card`,
  `can_move_card`, `can_comment`, `can_manage_columns`) computed by `can()`. The UI
  renders a control only when the server says it would accept it.
- `CardDto` carries `actor_label` and `mine`; the second is true only for the anonymous
  actor who created the card.
- The readable URL resolves for a credential-less caller **when the board accepts
  anonymous writes**. Otherwise `/users/:u/boards/:s/resolve` still answers `404`.

The anonymous PATCH rule is "the fields you may not change must come back unchanged",
not "the fields you may not change must be absent": the editor posts the whole form, so
an anon editing a title sends the tag list it already has. Any real difference answers
`403` naming the field.

### Two decisions this task made

1. **The cookie names a row, not the token.** `klui_link` is a signed
   `linkId.boardId`, httpOnly, `SameSite=Lax`, 30 days, and the link row is
   re-read on every request — that is what makes revocation immediate. One cookie
   covers every board a visitor holds a link for; `can()` still scopes the actor
   to its own board. Recorded in `docs/features/links-and-anonymous.md` §3.
2. **A token is only minted when the board would honour it.** On a board whose
   `link_role` is `none`, `POST /boards/:id/links` answers `400` naming
   `link_role` rather than handing out a credential that can never read.

### The defect this task exposed

A board page used to hang off the session guard, so a browser with a link cookie
and no session was redirected to `/login` before the board could ask `can()`.
`/boards/:id` and `/boards/:id/summary` now sit on a shell-only route: the page
distinguishes `404` (unreadable) from `401` (no credential at all) and offers the
sign-in link only in the second case.

### The defect this task found

`resolvePublicBoard` split four trailing characters **before** looking for the
exact slug, so `/<owner>/board-under-test` resolved board `board-under` with
suffix `test` and answered `404`. Every server test had passed because their
fixtures happened to end in longer words; the browser journey with the shared
`BOARD_NAME` ("Board under test") failed on the first run. The resolver now tries
the exact slug, then the suffixed form, and the regression test pins it.

### What is deliberately not here

- **OG images.** The `<head>` carries `og:title`, `og:description` and `og:url`;
  there is no rasterised preview yet. D-50 names `resvg` for that and the
  dependency is not installed, so the image is absent rather than faked.
- **Reading a `link` board as a stranger.** The readable URL is served and not
  indexed, but an anonymous visitor has no actor until K3-02 issues link tokens
  and K3-03 signs the anonymous cookie. `/users/:username/boards/:segment/resolve`
  answer `404` for a credential-less caller today, which is the honest answer.

**Decisions this task made.**

1. The anonymous buckets are **not** gated on `KLUI_RATE_LIMIT`. That flag is a
   comfort switch for development; the anonymous cap is the control that makes an
   open board survivable, so it is always on and configurable by number instead.
2. A banned address is refused on the anonymous paths only — joining and writing.
   It is not a network-wide lockout: an account signed in from the same address
   keeps working, which is the difference between a moderation tool and a
   self-inflicted outage.
3. The captcha contract with Cap is the small one Klui actually calls:
   `POST {KLUI_CAPTCHA_URL}/siteverify` with `{token}` and a bearer secret,
   answered by `{"success": true}`. A Cap deployment behind a path prefix needs a
   proxy that exposes that route; the alternative was guessing at a protocol this
   repository cannot test against.
