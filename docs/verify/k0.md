Data preservation, the only deploy proof that counts:

```
BEFORE          1 users, 0 boards, 4 migrations finished
AFTER RESTART   1 users, 0 boards, 4 migrations finished
$ docker compose -p klui-k1 down && docker compose -p klui-k1 up -d
healthz 200 {"status":"ok","version":"0.1.0","db":"up"}
                 1 users, 4 migrations finished
$ diff mtimes-before mtimes-after && echo "secret mtimes identical"
secret mtimes identical
```

Trap recorded from this run: a first `up -d` that fails (here: the old project
still held port 8099) leaves a container with a stale network, and it restarts
forever with `P1001: Can't reach database server`. `docker compose up -d
--force-recreate app` recreated it and it connected. A failed first `up` is not
a database problem until it is proven to be one.
