## K5-02 — Analytics, gated

`KLUI_ANALYTICS_URL` was declared in `env.ts` and read by nothing. It is now
consumed at request time by `server/src/public/analytics.ts`: an `onSend` hook
that rewrites `text/html` only, so the SPA shell, a prerendered profile and a
board page's head all get the tag from one place, and a fourth surface added
later gets it without anyone remembering this file.

## K5-05 — Deterministic digest

`KLUI_DIGEST_LLM_URL` stays unset: the digest is computed by
`server/src/digest/build.ts`, which is pure — input in, sections and text out, no
clock beyond the account's timezone, no I/O, no model. `server/src/digest/service.ts`
owns the storage and the deliveries, `server/src/digest/routes.ts` exposes the
four routes, and the five-minute sweeper in `server/src/server.ts` calls
`runDueDigests`.

What each section reads is the one place this build departs from the ADR's
phrasing. `docs/adr/0005-digest-determinism.md` and
`docs/features/digest.md` §2 say the digest is built from `events` since the
previous send. Done and In progress are: they read `card.completed` and
`card.moved` work (`card.updated` too) since `last_sent_at`. Overdue, Assigned to
you and Next are not events by nature — they ask what *is* the case now — so they
read the open cards of the boards the account can read, and a card the log
already placed in an earlier section is not repeated. That is also why the event
payloads gained the fields a reader needs: `card.completed` and `card.reopened`
now carry `title`, and `card.moved` carries `title` and `to_column_name`. Without
them the log held ids only, and a digest built from it could not print a title or
a column name without a join — the test below failed on exactly that before the
payloads changed.

## K5-07 — i18n, server side

The web had 401 keys in `en` and `fr`. The server had English literals: the error
envelope's `message` came from `defaultMessage(code)` in `lib/errors.ts`, the
validation hint was a string in `fromZod`, the reset mail spelled its subject and
three paragraphs inline, and the unsubscribe page was a `const`. They are keys
now, in `server/src/i18n/{en,fr}.json`, read through `translate()` and chosen by
`localeOf(request.headers['accept-language'])`.

The seam is `toWire`, not every call site: `AppError` records whether a message
was written by hand, and only an explicit one skips the catalogue. That is why 35
error codes became translatable without touching the services that raise them —
and why `fromZod` no longer needs to know a locale at all: it passes
`hintKey: 'error.validation.hint'` and the wire does the rest.
